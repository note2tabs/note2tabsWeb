# Blocked transcription submissions

Added 15 October 2026 on an isolated branch based on the live currency-parity/replay deployment. No limit, pricing, upgrade prompt, language copy, consent setting or validation decision changes.

The product event `transcription_submission_blocked` runs through the existing consent-aware analytics transport on both the homepage and `/transcribe`, including their localized routes. Existing `upload_validation_failed`, handoff, upgrade and technical-error events remain intact. Do not add the new event's total to legacy validation totals: the same rejection can intentionally have both events.

Properties include `blocked_reason`, `blocked_stage`, `surface`, `mode`, model implementation, subscription plan, sign-in/session status, file size/category, clip start/end/duration and applicable byte/second limits. Backend refusal events include status and the existing request correlation ID when available. Locale, acquisition, anonymous/session IDs and country enrichment use the existing analytics pipeline. No filename, input URL, uploaded content, raw error text or signed storage URL is added.

Reasons cover:
- Existing in-flight/auth-loading guards and the required sign-in handoff.
- Missing file, invalid YouTube URL, missing/reversed/out-of-bounds clip range and duration limits.
- Plan upload and pre-auth file-preservation limits.
- Email verification and Heavy-preview confirmation.
- Failed handoff save/navigation, missing saved input, failed restoration and pending paid entitlement.
- Server verification/credit gates, other server refusals and unusable responses.
- Pre-acceptance transport failure, with presign/storage/request stage separation.

`is_expected_gate` distinguishes normal product gates from technical failures. This is a product event, not a new exception alert. A preview confirmation or sign-in handoff can continue successfully: a blocked event is a stage interruption, not a permanent failed transcription. `auth_resume` events describe a restored-input gate rather than another Generate click. Count attempted-submission validation/server stages separately when measuring rejection rate. Do not interpret auth/confirmation totals as lost users without checking subsequent accepted transcription events.

A job already accepted/queued is not labeled a blocked submission merely because later navigation fails. Analytics exceptions cannot interrupt validation or upgrades. Explicit analytics opt-out still applies; transport/network loss can prevent observation, so this does not guarantee capture of every offline or opted-out attempt.

Validation: 186 test files / 1,090 tests passed; focused privacy/analytics tests and TypeScript passed after the final wiring changes; optimized production build passed. A production-build local proxy supplied a fake free session and captured telemetry locally. Browser tests on `/ja/transcribe` and `/pl/transcribe` selected a 99,403,543-byte video, clicked Generate and confirmed the existing 50 MB rejection, upgrade visibility, and delivered event context. No real sign-in, upload, transcription, credit spend or customer event was generated by these tests.
